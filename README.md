# Сладкий мост — маркетплейс сладостей Якутия ⇄ Донбасс

**Демо:** https://sladkiy-most.vercel.app · API: https://sladkiy-most-api.vercel.app/docs

**Запуск локально:** `docker compose up --build` → http://localhost:3000 (подробнее — в разделе «Запуск»).

Веб-приложение для межрегионального заказа кондитерских изделий со **сборными отправками («волнами»)**.
Кейс хакатона PEAK IT 2026, продвинутый уровень. Дизайн — по макетам Figma «Сладкий мост» (десктоп и мобильная версия).

## Стек

| Слой | Технологии |
|---|---|
| Фронтенд | **Next.js 15** (App Router, RSC), **React 19**, **TypeScript**, **Tailwind CSS 4** |
| Бэкенд | **Python 3.12+**, FastAPI, Pydantic 2, SQLAlchemy 2, Alembic |
| База данных | **PostgreSQL 16** |
| Тесты | pytest (домен, use cases, API на реальном PostgreSQL) |

## Архитектура (Clean Architecture)

```
backend/app/
  domain/            ← ядро: сущности, правила волн, тарифы, сезонность. Чистый Python, без зависимостей
    entities.py        Product, Wave, Order, статусы, направления
    logistics.py       расписание волн, тариф от заполнения, расчёт доставки, термоупаковка
    errors.py
  application/       ← сценарии (use cases); зависят только от domain и портов
    ports.py           интерфейсы репозиториев, UnitOfWork, Clock
    waves.py           расписание, витрина волн, предложения для корзины, смена статуса волны
    orders.py          расчёт, оформление, отмена, отслеживание
    catalog.py, analytics.py
  infrastructure/    ← реализация портов: PostgreSQL (SQLAlchemy), настройки, seed
  presentation/api/  ← FastAPI: роутеры, Pydantic-схемы, трансляция ошибок в HTTP
  main.py            ← composition root: связывает infrastructure и presentation
migrations/          ← Alembic

frontend/src/
  app/               маршруты: (shop)/… — витрина и оформление, admin/… — кабинет администратора
  features/          сценарии UI: корзина и состояние (shop), каталог, оформление, заказы, доставка
  widgets/           шапка, подвал, мобильная навигация, карточки товара и волны
  shared/            API-клиент и типы, форматирование, UI-примитивы
```

Зависимости направлены внутрь: `presentation → application → domain`, `infrastructure → application/domain`.
Бизнес-логика живёт только в бэкенде: фронтенд получает расчёт доставки из API
(`/api/waves/offers`, `/api/quote`, `/api/quote/estimate`).

## Запуск

**Docker (всё сразу):**
```bash
docker compose up --build      # http://localhost:3000, API — http://localhost:8000/docs
```

**Локально:**
```bash
# 1. PostgreSQL: база sladkiy_most, пользователь sm/sm (или задайте DATABASE_URL в backend/.env)
# 2. Бэкенд
cd backend
uv sync
uv run alembic upgrade head
uv run python -m app.infrastructure.seed       # каталог + демо-заказы
uv run uvicorn app.main:app --reload           # :8000, Swagger на /docs
# 3. Фронтенд
cd frontend
npm install
npm run dev                                    # :3000, /api/* проксируется в бэкенд (BACKEND_URL)
```

**Supabase.** База развёрнута в проекте Supabase «SladkiyMost» (схема + каталог + демо-данные уже загружены,
миграции Alembic отмечены как применённые). Достаточно указать в `backend/.env` строку подключения
Session pooler из Dashboard → Connect (с префиксом `postgresql+psycopg://`), см. `backend/.env.example`.
Таблицы закрыты RLS от публичного REST API Supabase — доступ к данным только через бэкенд.

Тесты: `cd backend && uv run pytest` (интеграционные тесты API используют базу `sladkiy_most_test`
или `TEST_DATABASE_URL` и пропускаются, если PostgreSQL недоступен).

Демо-доступы: покупатель — телефон `+7 (914) 123-45-67`; администратор — `/admin`, пароль `admin` (`ADMIN_TOKEN`, смените перед публичным показом).
Чтобы показать сезонные правила, задайте бэкенду `TODAY=2026-12-10` (зима) или `TODAY=2026-07-01` (лето).

## Развёртывание (Vercel + Supabase)

| Часть | Где | Настройки |
|---|---|---|
| Сайт (Next.js) | Vercel, проект `sladkiy-most`, Root Directory `frontend` | `BACKEND_URL=https://sladkiy-most-api.vercel.app` |
| API (FastAPI) | Vercel, проект `sladkiy-most-api`, Root Directory `backend`, регион `fra1` | `DATABASE_URL` (Supabase transaction pooler, порт 6543), `SERVERLESS=true`, `ADMIN_TOKEN` |
| База (PostgreSQL) | Supabase, проект `SladkiyMost` (eu-central-1) | отдельная роль `sm_app` с RLS-политиками только для неё |

Оба проекта Vercel подключены к ветке `master`: каждый пуш пересобирает сайт и API.
`SERVERLESS=true` включает режим без пула соединений и без prepared statements — так требует transaction pooler Supabase.

## Функционал (раздел 5 кейса)

| Требование | Где |

## Логика волн и расчёт доставки (`backend/app/domain/logistics.py`)

- Волны идут **раз в 14 дней в каждом направлении**, приём закрывается **за 3 дня** до отправки, срок доставки **10–14 дней**.
- Тариф за кг считается по загрузке партии **вместе с заказом**: до 50 % — 500 ₽/кг; более 50 % — 400 ₽/кг (−20 %);
  более 80 % — 325 ₽/кг (−35 %). Максимум партии — 300 кг, минимум для отправки — 50 кг.
- **Доставка = тарифицируемый вес × тариф**; вес = масса нетто × 1,1 (упаковка), минимум 0,5 кг.
- При закрытии сбора доставка всех заказов волны пересчитывается по итоговой загрузке — **цена может только снизиться**.
- Партия не набрала 50 кг → «Перенесена», заказы переходят в следующую волну направления.
- Декабрь–февраль и июнь–август — обязательная термоупаковка шоколада (+150 ₽); май и ноябрь — +7 дней к сроку.
- Статусы волны управляют статусами заказов: «Сбор закрыт» → «В сборке», «В пути» → «В пути», «Прибыла» → «На пункте выдачи».

### Допущения
- В одну отправку входят сладости одного региона: они едут к получателю в другой регион.
- Упаковка +10 % к весу; минимальный тарифицируемый вес 0,5 кг; пункт выдачи — бесплатно, курьер — 150 ₽.
- Каталог ДНР и производители условные; прошлые и текущие волны содержат условную загрузку «от других покупателей» (`DEMO_LOAD`).

## Бизнес-модель
Комиссия 15 % с продажи товаров; подарочное оформление (250 ₽); термоупаковка (150 ₽); корпоративные наборы (B2B).
Доставка продаётся по себестоимости доли в партии.
