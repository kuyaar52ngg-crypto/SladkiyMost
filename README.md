# Сладкий мост — маркетплейс сладостей Якутия ⇄ Донбасс

**Сайт:** https://sladkiy-most.vercel.app

## Стек

| Слой | Технологии |
|---|---|
| Фронтенд | **Next.js 15** (App Router, RSC), **React 19**, **TypeScript**, **Tailwind CSS 4** |
| Бэкенд | **Python 3.12+**, FastAPI, Pydantic 2, SQLAlchemy 2, Alembic |
| База данных | **PostgreSQL 16** |
| Тесты | pytest (домен, use cases, API на реальном PostgreSQL) |

## Архитектура 

```
backend/app/
  domain/            ← ядро: сущности, правила волн, тарифы, сезонность.
    entities.py        Product, Wave, Order, статусы, направления
    logistics.py       расписание волн, тариф от заполнения, расчёт доставки, термоупаковка
    errors.py
  application/       ← сценарии (use cases); зависят только от domain и портов
    ports.py           интерфейсы репозиториев, UnitOfWork, Clock
    waves.py           расписание, витрина волн, предложения для корзины, смена статуса волны
    orders.py          расчёт, оформление, отмена, отслеживание
    catalog.py, analytics.py
    auth.py            регистрация, вход (блокировка после 5 ошибок), первый админ, привязка Telegram
    uploads.py         проверка фото и подписанная ссылка на загрузку
    notifications.py   уведомления о заказах и волнах
  infrastructure/    ← реализация портов: PostgreSQL (SQLAlchemy), Supabase Storage, Telegram, Argon2/JWT
  presentation/api/  ← FastAPI: роутеры, Pydantic-схемы, трансляция ошибок в HTTP
  main.py            ← composition root: связывает infrastructure и presentation
migrations/          ← Alembic

frontend/src/
  app/               маршруты: (shop)/… — витрина и оформление, admin/… — кабинет администратора
  features/          сценарии UI: корзина и состояние (shop), каталог, оформление, заказы, доставка
  widgets/           шапка, подвал, мобильная навигация, карточки товара и волны
  shared/            API-клиент и типы, форматирование, UI-примитивы
```

Зависимости направлены внутрь: `presentation → application → domain`, `infrastructure → application/domain`.
Бизнес-логика живёт только в бэкенде: фронтенд получает расчёт доставки из API
(`/api/waves/offers`, `/api/quote`, `/api/quote/estimate`).

## Запуск

**Docker (всё сразу):**
```bash
docker compose up --build      
```

**Локально:**
```bash
# 1. Бэкенд
cd backend
uv sync
uv run alembic upgrade head
uv run python -m app.infrastructure.seed      
uv run uvicorn app.main:app --reload          
# 2. Фронтенд
cd frontend
npm install
npm run dev                                    
```




## Переменные окружения (бэкенд)

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | PostgreSQL (`postgresql+psycopg://…`) |
| `JWT_SECRET` | секрет подписи сессий — длинная случайная строка |
| `ADMIN_PHONE`, `ADMIN_PASSWORD` | первый администратор: создаётся при старте, если админов ещё нет |
| `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` | Supabase Storage для фото (публичный bucket `products`; без них фото пишутся в `backend/uploads/`) и письма Supabase Auth для восстановления пароля |
| `TELEGRAM_BOT_TOKEN` | бот для уведомлений (токен от @BotFather) |
| `TELEGRAM_WEBHOOK_SECRET` | необязательно: секрет вебхука, по умолчанию выводится из `JWT_SECRET` |
| `SITE_URL`, `API_URL` | адреса сайта и API — для ссылок в уведомлениях и регистрации вебхука |
| `COOKIE_SECURE` | `false`, если API открыт по http не на localhost |
| `SERVERLESS` | `true` на Vercel (пулер Supabase) |

Фронтенду нужен только `BACKEND_URL` — адрес API, куда Next проксирует `/api/*` (cookie сессии работает same-origin).

## Первый запуск

1. Задайте переменные окружения, примените миграции (`uv run alembic upgrade head`) и `seed` — он только создаёт расписание волн.
2. Войдите в `/admin` с `ADMIN_PHONE` и `ADMIN_PASSWORD`.
3. Каталог пустой — добавьте товары в «Товары»: фото перетаскиваются в форму (JPG, PNG, WEBP, AVIF, GIF, SVG как есть; HEIC, TIFF, BMP браузер переводит в JPEG), до 20 МБ и 10 фото на товар, первое — обложка.
4. Бот настраивается сам при первом обращении (вебхук и кнопка «Магазин» в меню бота; вручную — «Подключить бота» на дашборде). Нажмите «Подключить Telegram» — новые заказы и статусы партий начнут приходить в чат. Покупатели подключают уведомления в «Моих заказах» или просто входят через бота.

### Восстановление пароля

«Забыли пароль?» → `/reset`: по телефону или почте. Ссылка приходит в Telegram (если привязан, действует 1 час и
перестаёт работать после смены пароля) и на почту из профиля — письмом Supabase Auth со ссылкой входа. Ссылка ведёт
на `/reset`, API проверяет токен в Supabase и узнаёт подтверждённую почту. В Supabase → Authentication:

1. **URL Configuration**: Site URL — адрес сайта, в Redirect URLs добавить `https://<сайт>/reset`.
2. **Emails → SMTP Settings**: подключить свой SMTP — встроенная почта Supabase отправляет письма только адресам
   команды проекта и не больше нескольких в час.
3. Шаблон **Magic Link** можно переписать по-русски («Сменить пароль на „Сладком мосте“»), ссылку `{{ .ConfirmationURL }}` оставить.

## Функционал 

| Требование | Где |
|---|---|
| Двусторонний каталог, витрины «Сладости Якутии» / «Сладости Донбасса», карточки, фильтры, поиск, корзина | `/catalog`, `/product/[id]`, `/cart` |
| Сборные отправки: дата отправки, окончание приёма, заполненность партии | `/checkout/wave`, главная, `/delivery` |
| Расчёт доставки от веса заказа и заполнения партии | `/checkout/calc`, калькулятор на `/delivery` |
| Отслеживание: принят → в сборке → в пути → на пункте выдачи → получен | `/orders`, `/orders/[code]` |
| Аккаунт покупателя: регистрация и вход по телефону, «Мои заказы»; гость открывает заказ по номеру и телефону | `/login`, `/orders` |
| Уведомления в Telegram: новый заказ, смена статуса, отмена, статусы партий | бот, кнопка «Подключить Telegram» |
| Личный кабинет покупателя: заказы и отслеживание, адреса, данные и настройки уведомлений, открытки, лента уведомлений, обращения в поддержку | `/account` |
| Админ-панель: дашборд, операционная карточка заказа, сборные партии (создание, правка дат и загрузки, удаление с переносом заказов, автосоздание по расписанию можно выключить), каталог с проверкой товаров, категории, продавцы, покупатели и обращения, отзывы с модерацией, аналитика, контент сайта (объявление, первый экран, контакты), настройки (приём заказов, минимальная сумма, премодерация отзывов, свой доступ) | `/admin` |
| Живое обновление: открытые страницы (витрина, кабинеты, админка) сами подхватывают изменения примерно за 8 секунд — API отдаёт номер последнего изменения (`/api/live`), страница опрашивает его и перерисовывается | все страницы |
| Отзывы: оценка и текст по товарам из полученных заказов, ответ площадки, рейтинг на странице товара | `/account/reviews`, `/product/[id]` |
| Восстановление пароля: ссылка в Telegram и на почту (Supabase Auth) | `/reset` |
| Кабинет поставщика: свои товары (черновик → проверка → публикация), свои позиции в заказах и этапы подготовки, партии, аналитика, профиль магазина. Магазин и доступ создаёт администратор в разделе «Продавцы» | `/seller` |
| Telegram Mini App: магазин открывается внутри Telegram (кнопка «Магазин» в меню бота и кнопки под уведомлениями), вход по Telegram без пароля после первой привязки | бот |
| Быстрая витрина: публичные данные кэшируются на сервере Next (60 с) и сбрасываются сразу после изменений в админке и новых заказов | — |
| Подарочный сценарий: получатель в другом регионе, открытка, подпись, сюрприз | `/gift`, шаг «Оформление» |
| Кабинет администратора (вход по паролю): товары с галереей фото, волны, статусы заказов | `/admin` |
| Оплата — имитация (заглушка) | шаг «Оформление» |
